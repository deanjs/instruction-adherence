# 3단계 — attention 개입 (P1a·P2)

주 가설 **H3**: attention/KV 개입이 준수 선호 점수를 **인과적으로** 바꾼다.
관련 계획서 절: 3.5(점수화), 3.6(개입). **논문의 진짜 새로움이 여기 있다.**

> 2단계는 "attention을 많이 준다"까지만 본다. 3단계는 그 attention/KV를 **직접 치환·조정**해
> 준수 결정이 바뀌는지 봄으로써 **인과 기여**를 확립한다. 오픈 모델(Qwen)에서만 가능.

---

## 방법론

### 준수 선호 점수 (3.5)

이진 판정은 개입 실험에 너무 거칠다. 연속 점수를 쓴다.

```
준수 선호 점수 = (1/|Y_c|)·log P(Y_c | X) − (1/|Y_v|)·log P(Y_v | X)
  Y_c 준수 표기 후보(getUserOrders), Y_v 위반 표기 후보(get_user_orders), teacher forcing
```

- **후보는 조건 공통의 사전 고정 문자열.** 모델이 실제 생성한 이름에서 뽑으면 조건 간 준수 선호 점수 차이가
  선호 차이인지 문자열 차이인지 구분 불가 → **모든 조건에서 동일한 두 문자열을 채점**한다.
- 실제 생성 이름은 별도 기록해 행동 판정에만 사용(두 측정 분리).
- 보조: 정확히 한 토큰에서 갈리는 사례의 logit 차이. 길이 정규화 편향 때문에 비정규화 로그확률차도 함께 보고.

### 개입 전용 pair (3.6) — 토큰 정확 일치

행동 실험의 ±3 토큰 허용을 **여기 적용 금지.** 1토큰만 달라도 위치 인덱스·RoPE가 어긋나 K/V 치환이 정의 안 됨.
→ 두 표기의 **총 토큰 수 동일 + 결정 지점 인덱스 동일** pair만 사용(Step 0에서 316쌍 확보).

### 조작 강도 — 다중 토글 (파일럿에서 확정)

주 context pair 하나만 토글하면 준수·위반 gap이 0에 가깝다(1차 파일럿에서 확인:
손상=준수=+1.19, gap≈0). camelCase 지침이 강해 함수 1개론 결정이 안 바뀐다 —
exp1도 효과는 위반이 **다수(8~12/12)** 일 때 났다. → 주 pair + 동반 matched pair
`(n_ctx−1)`개를 **함께 토글**한다(준수=전부 camel / 위반=전부 snake). 전부 토큰정렬
pair라 정렬 유지. 동반 pool은 A/B와 겹치지 않는 고정 집합(전 세션 공통). `--n-ctx`(기본 8).
클러스터 라벨은 여전히 **주 pair**라 (이름쌍×seed) two-way 구조가 유지된다.

### 왜 지침 구간을 교체하는 건 무의미한가 (3.6)

causal mask 때문에 지침 K/V는 두 조건에서 비트 단위로 동일 → 교체해도 아무 변화 없음.
조건 간 실제로 다른 건 **① 선행 코드 구간 K/V, ② 결정 지점 query(→ 지침에 대한 α도 달라짐)** 둘뿐.
지침 `v_i`는 같으므로 `c_I` 차이는 **오직 α 때문** — 이게 개입 설계를 결정한다.

### 네 가지 개입 — GQA 단위 주의

Qwen은 GQA(query head 28, KV head 4, 7:1 공유).

| 개입 | 조작 대상 | 단위 | 층당 수 |
|---|---|---|---|
| **P1a (주)** | query 고정, 코드 구간 K/V를 준수 실행 값으로 치환 후 α 재계산 | **KV group** | **4** |
| **P2 (보조)** | 위반 조건 내부에서 지침 구간 α에 배율 λ∈{0.5,1,2,4,8} (PASTA 계열, 양-반응) | query head | 28 |
| P1b (탐색) | 코드 구간 기여분 `c_C` 이식 | query head | 28 |
| P3 (탐색) | 지침 구간 기여분 `c_I` 교차 교체 | query head | 28 |

- **P1a를 query head 단위로 짜면 안 됨** — K/V는 group 내 7개 head가 공유하므로, 실제론 7개를 건드리면서 1개로 보고하게 됨. **P1a는 KV group 4개** 단위로 순회.
- 개입은 후보 함수명의 **모든 teacher-forcing step**에 동일 적용 후 sequence 수준 준수 선호 점수 계산(보조: 첫 토큰만).
- 질량 보존 변형을 주 결과(배분 변화만 분리), 비보존은 총량 변화 공변량으로 보고.

### 개입 효과 판정 (3.6)

- **주 지표 준수 선호 점수 변화량** = `개입본 준수 선호 점수 − 손상본 준수 선호 점수`. **준수 선호 점수로 표본을 선별하지 않는다**(순환 논증·평균 회귀 오독 방지). 선별 기준은 토큰 수 일치·함수명 속성·명세 슬롯 등 준수 선호 점수 무관 사전 기준만.
- **표본 분할:** A(50쌍)=기저 준수 선호 점수 변화량 추정 전용, B(50쌍)=개입 실행. Recovery Ratio = B의 준수 선호 점수 변화량 ÷ A의 기저 준수 선호 점수 변화량(분자·분모 상관 회피).
- **음성 대조**(효과가 **없어야** 함): no-op patch, 무관 구간 patch, R 구간 patch, 무작위 단위 patch.
  → 무작위 개입 준수 선호 점수 변화량 분포를 **귀무분포**로, P1a가 상위 꼬리인지 검정(**주 판정 기준**).
- 순회: P1a = 전 층 × KV group 4, P2 = 전 층 × query head 28. 음성 대조도 동일 범위.

### 절대 규칙 (완화 금지)

1. 준수 선호 점수 값으로 표본 선별 금지. 2. 후보는 전 조건 동일 문자열. 3. 개입 pair 토큰 수 정확 일치.
4. P1a는 KV group(4), P2/P1b/P3는 query head(28). 5. 주 가설은 H3.

### 주 조건과 귀무분포 (리뷰 반영)

- **주 개입 = `p1a_L25_allG`** — 2단계 split-half로 재현된 **L25 단독 × 전 KV group**에
  코드 K/V를 준수 값으로 이식. "L25가 준수 결정의 원인인가"를 직접 검정.
- **층별 개입** — 전 층 각각을 같은 규모(1층×전 group)로 돌려 `p1a_L{li}_allG`. 주 검정은
  아래 "확증 분석 계획"의 **대응 대비**(후기 층 평균·무작위 donor 대비)로 하고, 층별 순위는
  민감도로만 본다(전 층 순위는 초기 층 전파로 오염, 순위 p는 바닥 존재).
- **회복 상한** = `p1a_full`(전 층×전 group). Recovery Ratio 분자 상한.
- **단계적 범위(보조)** — 원인이 이름 토큰인지 이후 전파 표현인지 구분:
  `p1a_L25_name`(context 이름 토큰만) ⊂ `p1a_L25_func`(함수 전체) ⊂ `p1a_L25_allG`(선행 코드 전체).
- **대조**:
  - **무작위 donor**(`ctl_randdonor_L25` camel · `ctl_randdonor_snake_L25` snake) — 같은 L25·
    같은 위치·같은 토큰 수에 **비동일 clean K/V**(다른 pair들, 길이 일치). camel은 내용
    특이성(①a), camel↔snake 대비는 스타일 특이성(①b) 검정에 쓴다.
  - **동일 영역**(전부 조건 간 동일 → Δ≈0, 배관 검증): `ctl_noop`(donor=self, 정확 0)·
    `ctl_instr`(지침, 비트 동일)·`ctl_boiler`(코드 밖 보일러플레이트). 다중 토글에선 코드
    블록 전체가 조건 간 다르므로 단일 토글 때의 prectx/postctx는 오염돼 폐기.
- **P2** = 지침 α×λ. 전 층×전 head λ 곡선(**단조 추세 Spearman**) + 전 층 국소(층별 귀무).

### 통계 — two-way cluster bootstrap

- config당 (이름쌍, seed) 셀에 관측 1개뿐이라 (pair,seed) 단일 클러스터 재표본은 사실상
  iid라 반복 구조를 못 담는다. 그래서 **이름쌍 50개와 seed 3개를 각각 독립 복원추출**하고
  교차셀 평균을 통계로 쓴다(crossed two-way). 이게 이름쌍·seed 무선효과를 반영해 CI를
  적정하게 넓힌다(합성 검증: iid 폭의 약 3배).
- **주 유의성 = L25 Δ의 two-way 부트 95% CI가 0을 배제하는가** + 대조=0 + 단계 용량-반응.
- Recovery Ratio는 분자(B config)·분모(A gap)의 **독립 two-way 부트 분포**를 짝지어 비율 CI.
- P2 λ 단조성 = λ vs 평균 Δ의 Spearman ρ.

### 확증 분석 계획 (사전 등록, v3) — 파일럿 교훈 반영

**v2 파일럿에서 발견:** 단일 층 K/V 이식은 **downstream 전파**돼, 입력에 가까운 초기 층을
건드리면 사실상 코드를 통째로 교체한 셈이라 자명히 full 회복이 된다(`p1a_L0 ≈ p1a_full`).
초기 층의 양·음 전파도 관측됨(L2·L3 음수). → **전 층 교환가능성(exchangeability) 가정이
위배**될 수 있다. 순위 기반 p는 바닥 1/(귀무 층수+1)이라 후기 11~18층으로도 0.05 미만 불가.

이에 다음을 **사전 등록**한다:

1. **파일럿(v2, B pair 앞 `PILOT_PAIRS=10`쌍) 분리** — 설계용으로만 쓰고 확증서에서 제외.
   확증은 **홀드아웃**(`--pair-start 10`, design_version=v3)에서만.
2. **후기 층 범위 사전 고정** = 모델 마지막 1/3(구조 기준, 결과 무관; 36층이면 L24~L35).
   L25 주변 임의 선택 금지.
3. **주 검정 = 대응 대비의 two-way bootstrap 95% CI가 0을 배제하는가**(순위 p 아님):
   - **①a 내용 특이성:** Δ(L25 준수 donor) − Δ(**L25 무작위 camel donor**) > 0.
     무작위 donor = 같은 L25·같은 위치·같은 토큰 수에 **비동일 clean K/V**(다른 pair들, camel).
     >0면 준수-코드 **내용**이 특이적. ≈0/음수면 내용 무관(camel이면 뭐든 회복).
   - **①b 스타일 특이성:** Δ(무작위 **camel**) − Δ(무작위 **snake**) > 0. 내용은 같은 무작위로
     고정하고 **case만** 다르게 → camelCase **스타일**이 회복을 구동하는지 분리.
     ①a≈0·①b>0 = "내용 아닌 case-스타일 특이", ①a>0 = 내용 특이, 둘 다≈0 = 아무 코드.
   - **② 층 특이성:** Δ(L25) − mean(사전 고정 후기 층 제외본) > 0.
   - **③ 회복:** Δ(L25 준수 이식) > 0.
4. **민감도 분석:** 기존 전 층 순위·후기 순위 p를 삭제하지 않고 그대로 보고(검정 아님, 순위 근거).
5. **탐색:** L0의 강한 회복, 초기 층 양·음 전파 효과.

> 논문 기술: "파일럿에서 초기 층 개입의 downstream propagation으로 전 층 교환가능성 가정이
> 위배될 수 있음을 발견하여, 파일럿 표본을 확증 분석에서 제외하고 사전 정의된 후기 1/3 층을
> 대상으로 L25와 후기 층 평균의 대응 대비 및 비동일 무작위 donor 대비를 주 검정으로 등록,
> 기존 전 층 순위 분석은 민감도 분석으로 유지하였다."

### 하네스가 절대 규칙을 강제하는 방식

- **규칙 1:** A/B 분할은 고정 seed 셔플만 — 준수 선호 점수를 선별에 절대 참조 안 함.
  Recovery Ratio 분자(B)·분모(A)는 분리 표본.
- **규칙 2:** 결정 후보는 **작업과 의미가 맞는 고정 쌍** `formatValue`/`format_value`(camel=준수).
  모든 조건·개입에서 동일 채점. 실제 생성 이름은 이 스크립트에서 안 씀(측정 분리).
- **규칙 3:** `prepare_session`이 준수/위반 프롬프트를 대조, **코드 구간 밖 상이 시 폐기**.
  후보 토큰이 조건에 의존하면(`cand_context_dependent`) 폐기.
- **규칙 4:** P1a는 pre-repeat `key/value`의 `kvh` 축(=KV group)을 `index_copy_` 치환 —
  group 내 공유 query head를 함께 건드림이 자명. P2는 post-softmax α의 `H` 축(=query head).
  V4가 `n_q % n_kv == 0` 정합과 head 수를 보고(1.5B은 12×2, 개입 3B은 실제 head 수 사용).
- **규칙 5:** 출력은 새 파일 `stage3_intervention.jsonl`. 기존 `results/`는 불변.

### 개입 메커니즘 메모

- **채점은 전체 시퀀스 정사각 forward**로 한다(`[프롬프트 + 후보]` 한 번에). 캐시 재사용
  (`past_key_values`)은 query 길이≠key 길이에서 SDPA `is_causal`이 좌상단 정렬로 오정렬돼
  후보가 prefix를 못 봤다(파일럿에서 gap=0·V7=0로 드러남). 정사각 forward는 그 문제가 없다
  (V1로 검증). **Colab의 "prefix 캐시 1회 재사용" 최적화는 정확성을 위해 포기** — P2 대규모
  스윕 속도는 이후 별도 최적화(예: prefill 은닉상태 캐시).
