# 2단계 — attention 관측 (지침 참조 비율)

**질문:** 1단계에서 확인한 행동(위반 코드가 준수율을 낮춤)이 일어날 때,
모델이 실제로 **위반 코드 구간을 더 참조(attention 배분)** 하는가?
관련 계획서 절: 3.4(꺼내기), 3.7(지표).

> 이 문서는 **목표 → 가설 → 방법론 → 결과 → 한계 → 결론**의 읽기용 보고서(§1~6) 뒤에
> **날짜별 진행 트레일(사전 등록 기록)**을 붙인 통합본이다.
> **이건 상관 관측이지 인과 주장이 아니다.** "attention을 많이 줬다"가 "그게 원인이다"는 아니다
> (Jain & Wallace 2019 등). 인과 주장은 전적으로 3단계 개입에 근거한다.
> **오픈 모델(Qwen)에서만 가능** — 가중치·내부 접근이 필요.

---

## 한눈에 (쉬운 설명)

- **2단계가 한 일**: 1단계에서 "앞에 위반 코드가 쌓이면 규칙을 덜 지킨다"는 행동을 봤다.
  2단계는 **그때 모델이 실제로 어디를 보는지(attention)** 를 관측했다.
- **처음 예상**: "위반이 쌓이면 모델이 규칙(지침)에서 눈을 떼겠지."
- **실제로 본 것**:
  1. **지침을 보는 정도는 조건이 바뀌어도 거의 그대로**였다 → 모델은 규칙에서 눈을 떼지 않는다.
     (처음 예상은 빗나감.)
  2. 대신 모델은 **지금 규칙과 어긋나는(위반) 앞 함수 이름을 더 본다.**
  3. 이걸 확실히 하려고 두 겹으로 걸러냈다: **① 같은 위치·같은 길이에서 이름만 바꿔** 재서 구간 크기
     착시를 없애고, **② 지침을 camel/snake로 뒤집는 2×2**로, attention이 높아지는 게 **"snake 글자라서"가
     아니라 "지침과 충돌하는 상태라서"** 임을 분리했다.
- **한 줄 요약**: 모델은 "규칙을 **안 본다**"가 아니라 "규칙을 **어기는 앞 예시를 더 본다**."
- **선긋기**: 이건 **상관** 관측이다(원인은 3단계에서 직접 바꿔 확인). 그리고 이 관측으로 다음 단계 개입에
  쓸 **후보 층(L25 등)** 을 골랐다.

> 아래는 이 요약의 근거를 **목표 → 가설 → 방법 → 결과 → 한계 → 결론** 순으로 자세히 편 보고서다.

---

## 1. 목표와 질문

1단계(실험 1)에서 통제 실험으로 확립한 행동:
**context에 누적된 위반 코드가 뒤이어 생성되는 함수의 규칙 준수율을 낮춘다.**

2단계의 질문은 **"그 행동이 일어날 때 모델의 attention 배분에서 무엇이 관찰되는가"** 이다.
가장 직관적인 가설은 "위반이 쌓이면 모델이 규칙(지침)을 덜 참조한다"이지만, 이를 포함해
**규칙 참조 / 선행 코드 참조 / 위반 코드 참조**가 조건에 따라 어떻게 달라지는지를 잰다.

- 이 단계는 **상관 관측**이다. attention 크기는 출력에 미친 영향력과 같지 않으므로
  (Jain & Wallace 2019; Serrano & Smith 2019) 여기서 인과를 주장하지 않는다. 인과는 3단계 개입.
- 가중치·내부 접근이 필요하므로 **오픈 모델(Qwen2.5-Coder-3B)에서만** 수행한다.

## 2. 가설과 그 지위

| 가설 | 내용 | 지위 |
|---|---|---|
| H5 | 위반 조건에서 지침 구간 참조 비율이 더 낮다 | **탐색적 보고** |
| H6 | Violation-style 조건에서 선행 코드 참조가 더 높다 | 탐색적(추가 실험 A 영역, 보류) |

**주 가설은 H1a·H2a·H3 뿐**이다(CLAUDE.md 규칙 6). 2단계 관측은 전부 탐색적이며,
사후에 주 가설로 승격하지 않는다. 아래 결과의 "확증"은 **주 가설 확증이 아니라
관측된 효과가 로버스트하게 재현된다**는 의미다.

## 3. 방법론

### 3.1 attention 캡처 (계획서 3.4)

전체 attention matrix 저장은 불가능하다(16K context에서 층당 ~15GB). 필요한 것은 prefill
matrix가 아니라 "새로 생성되는 토큰이 context의 어느 구간을 참조하나" = **decode 단계의
query 한 행**뿐이다. 그래서 `AttentionInterface`에 **query 길이로 분기**하는 함수를 등록한다.

- `q_len > 1` (prefill) → SDPA에 위임, attention 미계산(메모리 폭증·FlashAttention 비호환 회피).
- `q_len == 1` (decode) → 명시적 softmax → **구간별 합으로 즉시 축약, 축약값만 저장.**
- GQA(실행 3B: K/V head 2, query head 16, 8:1)라 `repeat_kv` 처리. head 수는 config에서 읽음.
- **naming step 측정용**: prefill의 **마지막 query 행**(= 다음 토큰=함수 이름을 예측하는 위치)만
  따로 명시적으로 축약(한 행이라 메모리 폭증 없음).

**커널 검증(필수 게이트).** prefill/decode가 다른 커널이므로, 512토큰 짧은 시퀀스에서
`output_attentions=True` eager 결과와 캡처 축약값이 수치 일치하는지 확인한다.
→ **PASS: 2632쌍 비교, 최대 절대오차 5.96e-07 (tol 1e-3).** 이후 모든 수치가 이 검증 위에 있다.

### 3.2 지표 (계획서 3.7)

- **길이 정규화 참조 비율(NIAR류).** 단순 attention 합은 context가 길어지면 지침 구간이
  참조 정도와 무관하게 자동 감소하므로 길이로 정규화한다.
  ```
  지침 참조 비율 = (지침 구간 attention 합 ÷ 지침 토큰 수) ÷ (전체 attention 합 ÷ 전체 토큰 수)
  ```
  균등 분포면 context 길이와 무관하게 1 → "지침이 짧아서"라는 반론 차단. 동일 방식으로
  선행 코드·위반 코드 참조 비율 정의.
- **동일 길이 구간 대조.** 토큰 수가 같은 구간끼리는 정규화 없이 raw attention 합을 직접 비교.
- **보완 지표 `‖αv‖`(Kobayashi 2020에서 착안).** attention이 높아도 value가 작으면 실제
  기여가 작다는 점을 반영. **단 본 구현은 output projection 이전의 `‖αv‖`** 이며, Kobayashi
  원식 `‖αf(x)‖`(output projection 포함)와 구별한다.
- **교란 통제.** attention sink(Xiao 2024) 앞 4토큰을 구간·분모 양쪽에서 제외.
  위치 편향(Liu 2024)은 지침을 전 조건 동일 위치 고정, 대응 입력은 토큰 수준 정렬로 통제.

### 3.3 세 가지 측정 (점증적으로 교란 제거)

| 측정 | 설계 | 무엇을 분리하나 |
|---|---|---|
| **1. 조건 관측** (`--observe`) | exp1 조건(남은 준수 예시 수 cr∈{4..0})·seed 재사용. 지침/선행/위반 참조 비율을 조건별·층별로 | 조건에 따른 참조 변화(하지만 구간 크기 교란 있음) |
| **2. 내용-분리** (`--content`) | Step 0 **토큰 수 일치 pair**로 같은 위치·같은 길이에서 target 이름만 camel↔snake 교체. naming step의 이름 토큰 attention | 구간 크기·위치를 제거한 **순수 내용 효과** |
| **3. 지침 뒤집기 2×2** (`--content2x2`) | 지침을 camelCase/snake_case로 뒤집어 {지침2}×{이름2}. 관측당 4 forward, filler도 지침 따라 뒤집어 대칭 | **snake 토큰 특성 vs 지침 위반 상태** 분리 |

측정 2·3의 입력은 exp1_main의 `build_prefix`/`system_prompt`를 그대로 import하고 정본과
`assert`로 대조해 **행동↔관측 조건 동일성**을 보장한다. 대응 입력은 토큰 정렬을 assert하고,
안 맞는 pair는 조용히 버리지 않고 폐기 수를 집계한다.

#### 2×2 분해 (측정 3의 핵심)

```
지침         camel 이름   snake 이름
camelCase     준수          위반
snake_case    위반          준수
```
한 대응 관측에서:
- Δ_A = (camelCase 지침) snake − camel   [snake = 위반]
- Δ_B = (snake_case 지침) snake − camel   [camel = 위반]
- **토큰-identity 효과 = (Δ_A + Δ_B)/2** — 지침을 뒤집어도 남는 snake 성향
- **위반-상태 효과 = (Δ_A − Δ_B)/2** — 이름스타일 × 지침 상호작용 = "위반이라서"

### 3.4 통계 (반복 측정 구조 반영)

한 이름쌍이 여러 문맥 seed에서 반복되고, 한 문맥 seed가 여러 이름쌍에서 반복되는 **교차 자료**다.
따라서 관측을 독립 표본으로 보는 순진한 SE는 과대평가된다. 이를 피하려고:
- **이름쌍 clustered SE** + **이름쌍 cluster bootstrap 95% CI**(문맥 seed 반복 고려).
- **split-half 층선정**: 문맥 seed의 절반으로 후보 층을 탐색하고 나머지 절반으로 재현 확인,
  **재현된 층만** 3단계 개입 대상 후보로 남긴다.

### 3.5 확정 절차 6단계 (파일럿 → 확증)

1. 지침 두 문장이 강도·토큰 수·위치에서 대응하는지 점검(`--check-instr`).
2. snake_case 지침도 모델이 실제 이해·준수하는지 행동 점검(`--behcheck`).
3. 80 이름쌍 × 문맥 seed 20으로 재실행.
4. 이름쌍·문맥 seed cluster bootstrap 95% CI.
5. seed 10 탐색 / 10 재현 split-half 층선정.
6. 재현된 층만 개입 대상.

### 3.6 모델·설정

Qwen2.5-Coder-3B-Instruct, **fp16(양자화 없음)**, exp1 확증과 동일 모델(행동↔관측 연속성).
관측은 재현성 위해 greedy. 결과는 세션 단위 JSONL append + `(model, condition, seed)` 재개.

## 4. 결과

### 4.1 측정 1 — 조건 관측 (`stage2_niar_v1`, cr{4..0}×20 seed)

- **지침 참조 비율: 조건 무관(평탄).** 전체 평균 전 조건 0.30, 층별로도 평탄(|Δ| 최대 L27 +0.052,
  오히려 H5 반대 방향·노이즈). → **"위반 조건에서 지침을 덜 본다(H5)"는 관측되지 않음.**
  부수: L27이 지침을 평균 이상 참조하는 유일한 층(지침 참조 비율 ≈ 1.8).
- **선행 코드 참조 비율: 평탄**(|Δ| 최대 +0.012).
- **위반 코드 참조 비율: 큰 gradient(L25 +0.142 등)가 있으나 구간 교란.** cond0(전부 위반)에선
  위반 구간 = prefix 전체라 위반 참조 비율이 선행 코드 참조 비율로 수렴 — L25·L20에서 두 값이
  **소수점까지 동일**(0.402=0.402, 0.296=0.296). 내용 효과와 구간 크기가 분리 안 됨 → **판정 보류.**

### 4.2 측정 2 — 내용-분리 (`stage2_content_v1`, 80쌍×3 seed = 240 대응 관측)

같은 위치·같은 길이에서 이름만 교체(camelCase 지침 고정). naming step 이름 토큰:

| 지표 | camel | snake | 상대 |
|---|---|---|---|
| raw attention | 0.0033 | 0.0039 | 약 +18% |
| `‖αv‖`(output projection 이전) | 0.0352 | 0.0417 | 약 +18% |

구간 교란을 제거해도 이름 토큰 참조가 증가 → 측정 1의 gradient가 전부 교란은 아님.
**단 "snake 토큰 특성"과 "지침 위반 상태"가 분리 안 됨**(지침이 camelCase 고정이라 snake=위반).

### 4.3 측정 3 — 2×2 지침 뒤집기: **확증** (`stage2_flip2x2_v1`)

**게이트(절차 1·2).** 지침 두 문장 rule = 각 7토큰(대응 ✅). 행동 준수율 camelCase **10/10**,
snake_case **10/10** → **모델이 두 지침 다 준수** → 양쪽 셀에서 위반 상태가 실제로 성립.

**본 측정(절차 3~6).** 80 이름쌍 × 문맥 seed 20 = **1600 대응 관측**, 정렬 폐기 0, bootstrap 2000회.

| 성분 | raw attention (95% CI) | `‖αv‖` (95% CI) |
|---|---|---|
| 토큰-identity | −0.00026 [−0.00029, −0.00022] | −0.00397 [−0.00435, −0.00358] |
| **위반-상태** | **+0.00089 [+0.00086, +0.00093]** | **+0.01104 [+0.01058, +0.01150]** |

- **위반-상태 효과가 양(+)이고 CI가 0을 제외**(두 지표). seed 3 파일럿(+0.00089 / +0.01101)과
  거의 동일하게 재현.
- **토큰-identity 성분은 명확히 음수**(CI 0 제외) → snake 토큰 자체의 저수준 saliency로는
  설명 안 됨(반대 방향).
- **수치 정합.** 성분을 셀 조건으로 되풀면 측정 2가 복원된다: camelCase 지침 raw
  = −0.00026+0.00089 = +0.00059 ≈ 측정 2의 +0.0006; `‖αv‖` = +0.00651 ≈ +0.0065.
  지침을 뒤집으면 attention 방향도 뒤집힘 → **표기 토큰이 아니라 충돌 상태가 원인.**

**split-half 층선정(탐색 seed 10 / 재현 seed 10, 위반-상태 Δ raw).** 재현된 개입 후보 층:
**L25(단독 지배, +0.011) · L7 · L31 · L27 · L15 · L20 · L34 · L33** — 전부 탐색↔재현 방향·양수 일치.
→ 측정 1의 교란 섞인 L20~32 추측을 **데이터 기반 재현 층으로 대체.** 3단계 개입은 **L25 우선.**

## 5. 인과 지위와 한계

**두 링크를 구분한다.**
- **링크 1 (지침 위반 상태 → 이름 토큰 attention 증가): 확증.** 지침을 직접 뒤집는 입력 조작에
  따른 효과이며(단순 상관 아님), (a) bootstrap CI 0 제외, (b) split-half 재현, (c) 두 지침 모두
  실제 준수로 로버스트.
- **링크 2 (attention 증가 → 실제 위반 출력): 미확인.** 그 attention이 모델의 최종 위반 행동을
  일으켰는지는 이 관측으로 못 본다. → **3단계 개입에서 검정.**

**한계.** 단일 모델(3B). naming step·단일 이름 토큰·전 층/선정 층 기준. 탐색적(주 가설 아님).
지침 표기 방향 두 가지(camelCase/snake_case)만 검증. 효과의 절대 크기는 작다(작지만 로버스트).

## 6. 결론

- **지침 참조(H5): 관측되지 않음.** 모델은 위반이 쌓여도 규칙에서 눈을 떼지 않는다.
- **핵심 관측:** 모델은 특정 표기법 토큰을 일관되게 더 참조하는 것이 아니라,
  **현재 지침과 충돌하는(=위반하는) 선행 함수 이름에 더 많은 attention을 배분**한다.
  이는 입력 조작 효과로 로버스트하게 확증됐다(raw·`‖αv‖` 일치, CI 0 제외, split-half 재현).
- 메커니즘 그림: "규칙을 안 본다"가 아니라 "**규칙을 위반하는 선행 예시를 더 참조**"한다는 쪽.
- **3단계로.** 이 참조가 준수 결정의 **원인**인지 개입으로 검정한다. 개입 후보 층은
  split-half로 재현된 **L25(우선) 등**, 개입 pair는 본 단계에서 쓴 토큰 수 일치 pair.

### 2026-08-03 — 1차 관측: 지침 참조는 조건 무관(평탄), 위반 코드 gradient는 구간 교란으로 판정 보류

**설정.** `stage2_niar_v1`, 3B, 조건 = 남은 준수 예시 수 cr∈{4..0}(=위반 8..12개),
조건당 20 seed(exp1과 공유), greedy, 생성 48토큰 평균, 층별 profile 저장.
층별 진단은 `--observe --layer-summary`로 Δ=조건0(위반多)−조건4(준수多)를 층별 계산.

**① 지침 참조 비율 — 조건 무관(H5 관측 안 됨).**
전체 평균(모든 조건 0.30)뿐 아니라 **층별로도 평탄**. |Δ| 최대가 L27의 **+0.052**로,
오히려 H5 반대 방향(위반 많을 때 지침을 *더* 참조)이고 노이즈 수준. 나머지 층 −0.01~−0.03.
→ **"위반 조건에서 지침 참조가 낮아진다(H5)"는 관측되지 않음.**

**② 선행 코드 참조 비율 — 평탄.** |Δ| 최대 L8 +0.012. prefix 전체 참조량은 구성비와 무관.

**③ 위반 코드 참조 비율 — 유일한 큰 gradient, 그러나 구간 교란으로 판정 보류.**
중·후반 층에 몰려 일관된 양(+): L25 **+0.142**, L20/L21/L27/L30/L32가 +0.07~+0.08.
표면적으론 "위반 늘수록 위반 코드를 더 참조".
**그러나 교란(데이터로 확인):** cond0(전부 위반)에선 **위반 구간 = prefix 전체**라 위반 코드
참조 비율이 선행 코드 참조 비율로 수렴한다 — L25·L20에서 cond0의 두 값이 **소수점까지 동일**
(각각 0.402=0.402, 0.296=0.296, 차이 0.0000). 반면 cond4에선 위반 subset이
선행 코드 평균보다 **낮다**(L25: 0.261 < 0.392). 즉 Δ의 상당 부분은 **위반 구간이 커져 prefix
평균으로 수렴한 것**이지 snake 토큰의 내용 효과가 아니다. 내용 효과와 구간 크기·위치 효과가
분리되지 않음 → **이 데이터만으로는 "위반 코드를 더 본다" 판정 불가.**

**④ 부수 소득(기술적, 교란 있는 1차 기준).** **L27이 지침을 평균 이상 참조하는 유일한 층**
(지침 참조 비율≈1.8, >1) — "지침 읽는 층". 위반/선행 코드 참조는 L20~32에 집중.
단 이 층들은 **교란 있던 1차 관측**에서 나온 값이라, 3단계 개입 후보로 **확정은 아니다**
(2차 대응 관측의 층별 분석으로 별도 선정 필요 — 아래 2차 참조).

**한계.** 상관·탐색적(H5/H6은 주 가설 아님). attention 크기 ≠ 인과(Jain & Wallace 2019).
측정창이 생성 48토큰 평균이라 **준수가 결정되는 naming step이 물타기**됐을 수 있음.

**다음 측정(교란 제거).** 계획서 3.7 **보조 검증(동일 위치·동일 길이 대조)** —
같은 함수 슬롯이 조건에 따라 snake↔camel로 바뀔 때 그 **고정 구간**의 attention을 비교.
구간 크기·위치를 고정해 순수 내용 효과만 남긴다. 대응 설계(nested·같은 seed)라 깔끔히 성립.
아울러 naming step(첫 decode) 한정 측정도 병행. → 아래 2차에서 실행.

### 2026-08-03 — 2차 내용-분리 측정: 동일 위치·길이 대응에서 snake 이름 토큰 참조 증가(잠정) (`stage2_content_v1`)

**설정.** Step 0 토큰 수 일치 pair 중 단일 토큰 분기 **80개 이름쌍 × filler 문맥 seed 3개
= 240개 대응 관측(총 480회 forward)**, 정렬 실패 0, 3B. 한 대응 관측 = 같은 filler 문맥에서
target 이름 토큰 하나만 camel↔snake로 바꾼 두 조건. **seed는 모델 생성 난수가 아니라
filler 코드 구성·순서를 바꾸는 문맥 seed.** 측정 = **naming step**(`def ` 직후 이름 예측
위치 = prefill 마지막 query 행)의 이름 토큰 attention. 길이 동일이라 비정규화 raw 비교.
`results/stage2_content.jsonl`.

**결과(기술 요약).** camel→snake 교체 시 이름 토큰에 대해:
| 지표 | camel | snake | 상대 |
|---|---|---|---|
| raw attention | 0.0033 | 0.0039 | 약 +18% |
| output projection 이전 `‖αv‖`(Kobayashi에서 착안) | 0.0352 | 0.0417 | 약 +18% |

두 지표가 같은 방향·비슷한 크기로 증가. 구간 크기·위치를 고정했으므로 1차 gradient가 전부
교란은 아니었고, snake 토큰 내용에 대한 **안정적 내부 반응 가능성**을 시사.

**아직 확정 못 하는 것 (문서 결론 제한).**
1. **표준오차가 반복 측정 구조를 반영 안 함.** 코드는 240개 차이를 독립 표본처럼 SE를 냈지만,
   같은 이름쌍이 seed 3개에서, 같은 문맥 seed가 이름쌍 80개에서 반복되는 **교차 자료**다.
   따라서 요약에 찍히는 `z`(40대)는 **기술 요약값일 뿐 확증 유의성이 아니다.** 이름쌍으로 묶은
   clustered SE, 나아가 이름쌍·문맥 bootstrap 또는 혼합모형으로 다시 계산해야 한다(문맥 seed도 확대).
2. **"snake 토큰 특성"과 "지침 위반 상태"가 분리 안 됨.** 지침이 camelCase 고정이라 snake=위반이
   붙어 있다. 지금 보인 것은 **"camelCase 지침 아래에서 snake 이름 토큰이 camel보다 더 높은
   attention·`‖αv‖`를 유발"**까지. 위반이라서인지 밑줄 든 토큰이 원래 두드러져서인지는 미분리.
   분리하려면 **지침도 뒤집어** 2×2로:

   | 지침 | camel 이름 | snake 이름 |
   |---|---|---|
   | camelCase 사용 | 준수 | 위반 |
   | snake_case 사용 | 위반 | 준수 |

   지침이 바뀌어도 항상 snake를 더 보면 토큰 특성, **지침과 충돌하는 이름을 더 보면 위반 상태 효과**.
3. **`‖αv‖`는 output projection 이전 값.** Kobayashi 원식 `‖αf(x)‖`는 output projection까지
   포함한다. 여기서는 "value가 작아 상쇄되지 않았다"까지만, **실제 출력 기여 증가는 확정 못 함.**
4. **층 선정 미완.** 위 종합에 적힌 L20~32는 **교란 있던 1차**에서 나온 층이다. 2차는 전 층
   평균만 봤으므로 이 결과로 후보 층을 확정할 수 없다. 240개 대응 관측의 **층별 snake−camel
   차이**를 따로 계산해 후보를 정해야 한다(데이터에 `*_by_layer` 저장돼 있음).

**결론 문구(논문용).**
> 동일 위치·동일 길이의 대응 입력에서 camel 이름 토큰을 snake 이름 토큰으로 교체했을 때,
> 이름 생성 직전 해당 토큰에 대한 평균 attention은 0.0033→0.0039로, output projection 이전
> `‖αv‖`는 0.0352→0.0417로 증가했다. 이는 snake 토큰 내용에 대한 안정적인 내부 반응
> 가능성을 보여주지만, 현재 분석의 표준오차는 반복 측정 구조를 반영하지 않았으며, snake 토큰
> 특성과 지침 위반 상태도 분리되지 않았다. 따라서 위반 상태 효과와 attention의 행동적
> 인과성은 아직 확정되지 않았다.

### 2026-08-03 — 2×2 결과: 효과는 **snake 토큰이 아니라 위반 상태** (`stage2_flip2x2_v1`)

이름쌍 80 × 문맥 seed 3 = **240개 대응 관측**(관측당 4 forward), 정렬 폐기 0, 3B.
이름쌍 clustered t.

| 성분 | raw attention | output projection 이전 `‖αv‖` |
|---|---|---|
| 토큰-identity (Δ_A+Δ_B)/2 | **−0.00030** (t≈−17) | **−0.00450** (t≈−20) |
| 위반-상태 (Δ_A−Δ_B)/2 | **+0.00089** (t≈+51) | **+0.01101** (t≈+43) |

- **위반-상태 성분이 양(+)이고 지배적**: 지침이 camelCase든 snake_case든, 모델은 **활성 지침을
  위반하는 이름**(snake든 camel든)을 더 참조. 두 지표 방향 일치.
- **토큰-identity 성분은 오히려 음(−)**: snake 토큰 자체의 저수준 saliency로는 설명 안 됨(반대 방향).
**수치 정합(측정 2 복원).** 성분을 실제 셀 조건으로 되풀면 1차 내용-분리 값이 정확히 재현된다.
- raw: camelCase 지침 = 토큰+위반 = −0.00030+0.00089 = **+0.00059** (측정 2의 +0.0006과 일치).
  snake_case 지침 = 토큰−위반 = **−0.00119** (위반인 camel 이름을 그만큼 더 봄).
- `‖αv‖`: camelCase = −0.00450+0.01101 = **+0.00651** (측정 2의 +0.0065와 일치). snake_case = **−0.01551**.
- 지침을 뒤집으면 attention 방향도 함께 뒤집힘 → 표기 토큰이 아니라 **충돌 상태**가 원인.

**인과 지위 — 두 링크를 구분해야 한다.**
- **링크 1 (지침 위반 상태 → attention 증가): 통제된 입력 조작에 따른 효과.** 지침(camelCase↔
  snake_case)을 직접 뒤집고 나머지를 정렬했으므로, "충돌 상태가 그 이름의 attention을 높인다"는
  **입력 조작에 대한 인과**로 말할 수 있다(단순 상관 아님). → 이번에 확보.
- **링크 2 (attention 증가 → 실제 위반 출력): 아직 미확인.** 그 attention이 모델의 최종 위반
  행동을 **일으켰는지**는 이 관측으로 못 본다. → 3단계 개입에서 검정.

**여전히 남는 한계.** t는 이름쌍 clustered **기술값**(문맥 seed 3개, bootstrap/혼합모형 미적용) →
확증 유의성 아님. 절대 크기 작음. 단일 모델(3B), naming step·전 층 평균. 층 선정은 별도
(`--content2x2` by-layer 확장 필요).

### (하네스) 지침 뒤집기 2×2 — `--content2x2` 구현 완료

`src/stage2_attention.py --content2x2`. 각 이름쌍·문맥 seed에서 **4 forward**:
{camelCase 지침, snake_case 지침} × {camel 이름, snake 이름}. filler도 지침 따라 뒤집어 대칭.

    지침         camel 이름   snake 이름
    camelCase     준수          위반
    snake_case    위반          준수

- Δ_A = (camelCase) snake−camel,  Δ_B = (snake_case) snake−camel.
- **토큰-identity = (Δ_A+Δ_B)/2** (지침 뒤집어도 남는 snake 성향)
- **위반-상태 = (Δ_A−Δ_B)/2** (이름스타일 × 지침 상호작용 = "위반이라서")
- 이름쌍 clustered t로 보고. `results/stage2_flip2x2.jsonl`.
- 판정: 위반-상태 Δ>0 유의 → "위반이라서 더 본다" 첫 분리 증거(상관). 토큰-identity만 크면 저수준 토큰 효과.
- 합성 데이터 스모크로 분해 검증(토큰 시나리오→토큰만, 위반 시나리오→위반만).

### 2026-08-03 — 2×2 확증 (6단계 통과): 위반-상태 효과 로버스트 (`stage2_flip2x2_v1`, seed 20)

**절차 1·2 게이트 통과.** 지침 두 문장 rule = 각 **7토큰**(대응 ✅). 행동 점검 준수율:
camelCase **10/10**, snake_case **10/10** → 모델이 **두 지침 다 준수** → 양쪽 셀에서 위반 상태 성립.

**절차 3~6.** 이름쌍 80 × **문맥 seed 20 = 1600 대응 관측**, 정렬 폐기 0. 이름쌍 cluster bootstrap 2000회.

| 성분 | raw attention (95% CI) | `‖αv‖` (95% CI) |
|---|---|---|
| 토큰-identity | −0.00026 [−0.00029, −0.00022] | −0.00397 [−0.00435, −0.00358] |
| **위반-상태** | **+0.00089 [+0.00086, +0.00093]** | **+0.01104 [+0.01058, +0.01150]** |

- 위반-상태 CI가 **0을 제외**(두 지표), seed 3 파일럿(+0.00089 / +0.01101)과 **거의 동일 재현**.
- 토큰-identity는 **명확히 음수**(CI 0 제외) → snake 토큰 자체는 덜 참조. 효과는 전부 위반-상태.

**split-half 층선정(탐색 seed 10 / 재현 seed 10, 위반-상태 Δ raw).** 재현된 개입 후보 층:
**L25(단독 지배, +0.011) · L7 · L31 · L27 · L15 · L20 · L34 · L33** (전부 탐색↔재현 방향·양수 일치).
→ 1차의 교란 섞인 L20~32 추측을 **데이터 기반 재현 층으로 대체.** 3단계 개입은 **L25 우선**.

**확증 지위.** "**지침 위반 상태 → 그 이름 토큰 attention 증가**"는 (a) 입력 조작(지침 뒤집기),
(b) bootstrap CI 0 제외, (c) split-half 재현, (d) 두 지침 모두 실제 준수 — 로 **로버스트하게 확증**.
남은 미확인은 **attention 증가 → 실제 위반 출력**(인과) 한 링크 뿐 → 3단계.
한계: 단일 모델(3B), naming step·단일 토큰, 탐색적(주 가설 아님).
