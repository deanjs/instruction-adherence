## 방법론

### 설계: 3 (선행 코드 스타일) × 2 (지침 제시 시점) 요인

| 선행 코드 스타일 | 내용 |
|---|---|
| **Compliant-style** | 동일 기능·동일 작업 코드, 지침을 지킨 표기 |
| **Violation-style** | 동일 기능·동일 작업 코드, 지침을 어긴 표기 |
| **Neutral** | 동일 토큰 길이의 무관한 코드 |

| 지침 제시 시점 | 내용 |
|---|---|
| **Before** | 지침이 선행 코드보다 앞 |
| **After** | 선행 코드가 먼저, 지침이 뒤 |

### 왜 세 스타일이 모두 필요한가

- **Violation-style vs Compliant-style** → 관련성·의미·API 동일, 표기만 다름 → **순수 스타일 효과**.
- **Compliant-style vs Neutral** → 스타일은 둘 다 지침과 일치, 작업 관련성만 다름 → **작업 관련 코드가 참조를 끌어당기는 효과**.

Violation-style과 Neutral만 비교하면 스타일 외 여러 요인(관련성·의미·API)이 섞여 원인을 못 가른다.

### 구성 원칙

- Compliant/Violation-style은 **동일한 함수들**을 표기만 바꿔 만든다(의미·변수명·API·주석 동일).
- Neutral은 두 조건의 평균 토큰 수에 맞추고, 세 조건 토큰 수를 ±3 이내 정렬(잔여차 공변량).

### 보조 조건 — 선행 코드 출처

Violation-style을 (a) 연구자 작성 고정본 vs (b) 같은 모델이 지침 없이 실제 생성한 코드로 나눠 비교(각 40세션). "선행 코드의 분포 특성이 결과를 바꾸는가"를 본다(자기 생성 인식 여부를 묻는 게 아님).

### 통계

실험 1과 동일한 GLMM 골격(6.4). H2a는 **스타일 × 시점 상호작용**으로 검정.
