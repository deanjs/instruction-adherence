# 2단계 — attention 관측 (지침 참조 비율)

**질문:** 1단계에서 확인한 행동(위반 코드가 준수율을 낮춤)이 일어날 때,
모델이 실제로 **위반 코드 구간을 더 참조(attention 배분)** 하는가?
관련 계획서 절: 3.4(꺼내기), 3.7(지표).

> **이건 상관 관측이지 인과 주장이 아니다.** "attention을 많이 줬다"가 "그게 원인이다"는 아니다
> (Jain & Wallace 2019 등). 인과 주장은 전적으로 3단계 개입에 근거한다.
> **오픈 모델(Qwen)에서만 가능** — 가중치·내부 접근이 필요.

---

## 방법론

### attention을 어떻게 꺼내나 (3.4)

전체 attention matrix 저장은 불가(16K에서 층당 ~15GB). 필요한 건 prefill matrix가 아니라
**"새로 생성되는 토큰이 context의 어느 구간을 참조하나"** = decode 단계 query 한 행뿐(층당 ~0.9MB).

- `AttentionInterface`에 **query 길이 분기** 함수 등록:
  - `q_len > 1`(prefill) → SDPA/FlashAttention에 위임, attention 미계산.
  - `q_len == 1`(decode) → 명시적 softmax → **구간별 합으로 즉시 축약, 축약값만 저장.**
- prefill 메모리 폭증 회피, `output_attentions=True` 불필요(FlashAttention 비호환 회피).
- **검증:** 512 토큰 짧은 시퀀스에서 전 구간 eager 결과와 수치 일치 확인(prefill/decode 커널이 달라 필수).

### 지표 — 길이 정규화 (3.7)

단순 attention 합 비율은 context가 길어지면 지침 구간이 **참조 정도와 무관하게 자동 감소**한다.
그래서 길이로 정규화:

```
지침 참조 비율 = (지침 구간 attention 합 ÷ 지침 토큰 수) ÷ (전체 attention 합 ÷ 전체 토큰 수)
  지침 참조 비율 = 1 → 평균 수준 참조,  > 1 → 평균보다 많이 참조
```

- 동일 방식으로 **선행 코드 참조 비율**, **위반 코드 참조 비율**을 정의.
- **핵심 성질:** 균등 분포일 때 지침 참조 비율은 context 길이와 무관하게 1 → "지침이 짧아서"라는 반론 차단.
- **보조:** 지침과 같은 토큰 수의 코드 구간 100회 무작위 추출해 attention 합 직접 비교(정규화 불필요).
- **보완 지표:** `‖α·v‖`(Kobayashi 2020) — attention이 높아도 value가 작으면 실제 기여 작음.

### 교란 통제 (3.7)

| 요인 | 처리 |
|---|---|
| attention sink (Xiao 2024) | 앞 4개 토큰 제외. 제외 여부 민감도는 부록 |
| 위치 편향 (Liu 2024) | 지침을 전 조건 동일 위치 고정, 조건 간 prefix 길이를 토큰 수준 정렬 |

### 예상 관측

위반 코드가 준수율을 낮추는 조건에서 **위반 코드 참조 비율이 상대적으로 높고 지침 참조 비율이 낮으면**,
"규칙보다 선행 코드를 더 참조한다"는 행동과 정합하는 관측이 된다. (여기까지는 상관.)

## 관찰 기록 (2단계)

### 2026-08-03 — 1차 관측: 지침 참조는 조건 무관(평탄), 위반 코드 gradient는 구간 교란으로 판정 보류

**설정.** `stage2_niar_v1`, 3B, 조건 = 남은 준수 예시 수 cr∈{4..0}(=위반 8..12개),
조건당 20 seed(exp1과 공유), greedy, 생성 48토큰 평균, 층별 profile 저장.
층별 진단은 `--observe --layer-summary`로 Δ=조건0(위반多)−조건4(준수多)를 층별 계산.

**① 지침 참조 비율 — 조건 무관(H5 관측 안 됨).**
전체 평균(모든 조건 0.30)뿐 아니라 **층별로도 평탄**. |Δ| 최대가 L27의 **+0.052**로,
오히려 H5 반대 방향(위반 많을 때 지침을 *더* 참조)이고 노이즈 수준. 나머지 층 −0.01~−0.03.
→ **"위반 조건에서 지침 참조가 낮아진다(H5)"는 관측되지 않음.**

**② 선행 코드 참조 비율 — 평탄.** |Δ| 최대 L8 +0.012. prefix 전체 참조량은 구성비와 무관.

**③ 위반 코드 참조 비율 — 유일한 큰 gradient, 그러나 구간 교란으로 판정 보류.**
중·후반 층에 몰려 일관된 양(+): L25 **+0.142**, L20/L21/L27/L30/L32가 +0.07~+0.08.
표면적으론 "위반 늘수록 위반 코드를 더 참조".
**그러나 교란(데이터로 확인):** cond0(전부 위반)에선 **위반 구간 = prefix 전체**라 위반 코드
참조 비율이 선행 코드 참조 비율로 수렴한다 — L25·L20에서 cond0의 두 값이 **소수점까지 동일**
(각각 0.402=0.402, 0.296=0.296, 차이 0.0000). 반면 cond4에선 위반 subset이
선행 코드 평균보다 **낮다**(L25: 0.261 < 0.392). 즉 Δ의 상당 부분은 **위반 구간이 커져 prefix
평균으로 수렴한 것**이지 snake 토큰의 내용 효과가 아니다. 내용 효과와 구간 크기·위치 효과가
분리되지 않음 → **이 데이터만으로는 "위반 코드를 더 본다" 판정 불가.**

**④ 부수 소득(기술적, 교란 있는 1차 기준).** **L27이 지침을 평균 이상 참조하는 유일한 층**
(지침 참조 비율≈1.8, >1) — "지침 읽는 층". 위반/선행 코드 참조는 L20~32에 집중.
단 이 층들은 **교란 있던 1차 관측**에서 나온 값이라, 3단계 개입 후보로 **확정은 아니다**
(2차 대응 관측의 층별 분석으로 별도 선정 필요 — 아래 2차 참조).

**한계.** 상관·탐색적(H5/H6은 주 가설 아님). attention 크기 ≠ 인과(Jain & Wallace 2019).
측정창이 생성 48토큰 평균이라 **준수가 결정되는 naming step이 물타기**됐을 수 있음.

**다음 측정(교란 제거).** 계획서 3.7 **보조 검증(동일 위치·동일 길이 대조)** —
같은 함수 슬롯이 조건에 따라 snake↔camel로 바뀔 때 그 **고정 구간**의 attention을 비교.
구간 크기·위치를 고정해 순수 내용 효과만 남긴다. 대응 설계(nested·같은 seed)라 깔끔히 성립.
아울러 naming step(첫 decode) 한정 측정도 병행. → 아래 2차에서 실행.

### 2026-08-03 — 2차 내용-분리 측정: 동일 위치·길이 대응에서 snake 이름 토큰 참조 증가(잠정) (`stage2_content_v1`)

**설정.** Step 0 토큰 수 일치 pair 중 단일 토큰 분기 **80개 이름쌍 × filler 문맥 seed 3개
= 240개 대응 관측(총 480회 forward)**, 정렬 실패 0, 3B. 한 대응 관측 = 같은 filler 문맥에서
target 이름 토큰 하나만 camel↔snake로 바꾼 두 조건. **seed는 모델 생성 난수가 아니라
filler 코드 구성·순서를 바꾸는 문맥 seed.** 측정 = **naming step**(`def ` 직후 이름 예측
위치 = prefill 마지막 query 행)의 이름 토큰 attention. 길이 동일이라 비정규화 raw 비교.
`results/stage2_content.jsonl`.

**결과(기술 요약).** camel→snake 교체 시 이름 토큰에 대해:
| 지표 | camel | snake | 상대 |
|---|---|---|---|
| raw attention | 0.0033 | 0.0039 | 약 +18% |
| output projection 이전 `‖αv‖`(Kobayashi에서 착안) | 0.0352 | 0.0417 | 약 +18% |

두 지표가 같은 방향·비슷한 크기로 증가. 구간 크기·위치를 고정했으므로 1차 gradient가 전부
교란은 아니었고, snake 토큰 내용에 대한 **안정적 내부 반응 가능성**을 시사.

**아직 확정 못 하는 것 (문서 결론 제한).**
1. **표준오차가 반복 측정 구조를 반영 안 함.** 코드는 240개 차이를 독립 표본처럼 SE를 냈지만,
   같은 이름쌍이 seed 3개에서, 같은 문맥 seed가 이름쌍 80개에서 반복되는 **교차 자료**다.
   따라서 요약에 찍히는 `z`(40대)는 **기술 요약값일 뿐 확증 유의성이 아니다.** 이름쌍으로 묶은
   clustered SE, 나아가 이름쌍·문맥 bootstrap 또는 혼합모형으로 다시 계산해야 한다(문맥 seed도 확대).
2. **"snake 토큰 특성"과 "지침 위반 상태"가 분리 안 됨.** 지침이 camelCase 고정이라 snake=위반이
   붙어 있다. 지금 보인 것은 **"camelCase 지침 아래에서 snake 이름 토큰이 camel보다 더 높은
   attention·`‖αv‖`를 유발"**까지. 위반이라서인지 밑줄 든 토큰이 원래 두드러져서인지는 미분리.
   분리하려면 **지침도 뒤집어** 2×2로:

   | 지침 | camel 이름 | snake 이름 |
   |---|---|---|
   | camelCase 사용 | 준수 | 위반 |
   | snake_case 사용 | 위반 | 준수 |

   지침이 바뀌어도 항상 snake를 더 보면 토큰 특성, **지침과 충돌하는 이름을 더 보면 위반 상태 효과**.
3. **`‖αv‖`는 output projection 이전 값.** Kobayashi 원식 `‖αf(x)‖`는 output projection까지
   포함한다. 여기서는 "value가 작아 상쇄되지 않았다"까지만, **실제 출력 기여 증가는 확정 못 함.**
4. **층 선정 미완.** 아래 종합에 적힌 L20~32는 **교란 있던 1차**에서 나온 층이다. 2차는 전 층
   평균만 봤으므로 이 결과로 후보 층을 확정할 수 없다. 240개 대응 관측의 **층별 snake−camel
   차이**를 따로 계산해 후보를 정해야 한다(데이터에 `*_by_layer` 저장돼 있음).

**결론 문구(논문용).**
> 동일 위치·동일 길이의 대응 입력에서 camel 이름 토큰을 snake 이름 토큰으로 교체했을 때,
> 이름 생성 직전 해당 토큰에 대한 평균 attention은 0.0033→0.0039로, output projection 이전
> `‖αv‖`는 0.0352→0.0417로 증가했다. 이는 snake 토큰 내용에 대한 안정적인 내부 반응
> 가능성을 보여주지만, 현재 분석의 표준오차는 반복 측정 구조를 반영하지 않았으며, snake 토큰
> 특성과 지침 위반 상태도 분리되지 않았다. 따라서 위반 상태 효과와 attention의 행동적
> 인과성은 아직 확정되지 않았다.

**2단계 종합(현시점).**
- 지침 참조(H5): 조건에 따른 변화 **관측 안 됨**(전 층 평탄).
- 위반코드 참조: 순진한 관측은 구간 교란으로 과장. 교란 제거 후 snake 이름 토큰에서
  attention·`‖αv‖`가 약 +18% — **잠정**(반복측정 SE·위반/토큰 분리·층 선정 모두 미완).
- 다음: (a) clustered/bootstrap SE + 문맥 seed 확대, (b) **지침 뒤집기(2×2)**로 위반 vs 토큰 분리,
  (c) 층별 snake−camel로 개입 후보 층 선정.

### (하네스) 지침 뒤집기 2×2 — `--content2x2` 구현 완료, 실행 대기

`src/stage2_attention.py --content2x2`. 각 이름쌍·문맥 seed에서 **4 forward**:
{camelCase 지침, snake_case 지침} × {camel 이름, snake 이름}. filler도 지침 따라 뒤집어 대칭.

    지침         camel 이름   snake 이름
    camelCase     준수          위반
    snake_case    위반          준수

- Δ_A = (camelCase) snake−camel,  Δ_B = (snake_case) snake−camel.
- **토큰-identity = (Δ_A+Δ_B)/2** (지침 뒤집어도 남는 snake 성향)
- **위반-상태 = (Δ_A−Δ_B)/2** (이름스타일 × 지침 상호작용 = "위반이라서")
- 이름쌍 clustered t로 보고. `results/stage2_flip2x2.jsonl`.
- 판정: 위반-상태 Δ>0 유의 → "위반이라서 더 본다" 첫 분리 증거(상관). 토큰-identity만 크면 저수준 토큰 효과.
- 합성 데이터 스모크로 분해 검증(토큰 시나리오→토큰만, 위반 시나리오→위반만). Colab 실행 대기.
