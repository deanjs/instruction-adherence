# 실험 로드맵 (단계별 한눈에 보기)

`연구계획서.md`는 전체 설계의 상세 원본이다. **이 폴더는 그걸 단계별로 쉽게 보도록 나눈 요약본**이다.
각 문서는 `방법론 → 결과` 순서이고, 아직 안 한 실험은 결과를 공백으로 둔다(나중에 채움).

## 전체 구조 (3단)

| 단계 | 내용 | 문서 |
|---|---|---|
| 예비 | 실험 1을 위한 초기 실험 (모델·규칙·조작 구간 결정) | [`00_예비실험.md`](00_예비실험.md) |
| 1단계 · 실험 1 | context 내 위반 코드 → 행동 수준 인과 (H1) | [`01_실험1.md`](01_실험1.md) |
| 1단계 · 실험 2 | 선행 코드 스타일 × 지침 제시 시점 (H1) | [`02_실험2.md`](02_실험2.md) |
| 1단계 · 실험 3 | 규칙 등급 비대칭 (H2) | [`03_실험3.md`](03_실험3.md) |

어느 단계에서 멈춰도 논문이 성립하도록 설계돼 있다. 1단계(실험 1~3)가 논문의 본체다.

- [x] **예비실험** — 모델(3B), 규칙(camelCase), 지침 강도(weak), 조작 구간(compliant 예시 수) 결정
- [ ] **실험 1** — 방법론 확정(재설계), 본 실행 대기

- [ ] **실험 3** — 방법론 정의됨, 미착수

## 주 가설 (사전 등록)

- **H1a** — context 내 위반 코드가 후속 함수의 규칙 준수율을 낮춘다 (실험 1)
- **H2a** — 선행 코드 스타일 효과가 지침 제시 시점에 따라 다르다 (실험 2)
- **H3** — attention 개입이 준수 성향을 인과적으로 바꾼다 (3단계)

나머지는 전부 탐색적 보고. 사후에 주 가설을 추가하지 않는다.

## 문서 규칙

- 각 실험 문서 끝에 **관찰 기록(날짜별)** 을 둔다. 실험별로 분리해 기록한다.
- 상세 설계·수식·통계는 `연구계획서.md`의 해당 절을 참조(각 문서에 절 번호 표기).
- 용어: 모델에게 함수 하나를 만들라고 주는 주문 = **"작업 지시"**.
